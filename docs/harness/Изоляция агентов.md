## Зачем это нужно

Агент изменяет файлы, запускает команды и читает ваш проект. Изоляция ограничивает эти действия.

Изоляция даёт три выгоды:

1. **Защита проекта.** Агент не изменяет основную директорию проекта напрямую.
2. **Параллельная работа.** Запустите несколько агентов. Их изменения не конфликтуют.
3. **Безопасность.** Агент не выходит за границы, которые вы задали.

## 1. Изоляция через git worktree (копия проекта)

### Как это работает

1. Вы даёте агенту задачу.
2. Git создаёт worktree проекта в директории `agent-task-{task_id}` и ветку `agent-task/{task_id}`.
3. Агент вносит все изменения в эту копию.
4. После завершения система создаёт коммит с изменениями агента.
5. Система сливает ветку задачи в ветку цели.
6. Система удаляет worktree.

### Кто решает, когда создавать копию

Профиль агента задаёт правило параметром `task_isolation`:

| Значение | Поведение |
|---|---|
| `required` | Всегда создавать копию. Запуск без идентификатора задачи (`task_id`) запрещён. |
| `optional` | По умолчанию. Копия создаётся только при явных параметрах запуска: `task_id` вместе с `base_branch` или `on_branch`. |
| `disabled` | Не создавать копию. Агент работает в общей директории проекта. |

Вы задаёте точку старта копии:

- `base_branch` — копия создаётся от указанной ветки.
- `on_branch` — копия создаётся на указанной существующей ветке.
- `on_branch: "goal"` — копия создаётся на ветке цели. Магическое значение требует `goal_id`. Предпочитайте явную форму: `on_branch: "agent-goal/{goal_id}"`.

Параметры `base_branch` и `on_branch` взаимоисключающие.

Гостевой режим: параметр `worktree_of: "<task_id>"` запускает субагента в существующем ворктри другой задачи. Гость не может коммитить, сливать и удалять дерево. Режим нужен ревьюеру: он получает прогретый кеш без создания копии.

### Ограничения

- Число копий одновременно: по умолчанию 3. Измените параметром `task_worktree_limit`.
- Анализ кода (языковые серверы) в копии запущен по умолчанию. Отключите параметром `task_worktree_language_servers: false` — это экономит память.

## 2. Несколько репозиториев в одном проекте

Проект может содержать несколько Git-репозиториев. Пример: папки `frontend/` и `backend/` — два отдельных репозитория. Вы указываете системе, где работает агент.

### Выбор репозитория

Задайте репозиторий при запуске агента:

```json
{
  "label": "Fix backend bug",
  "message": "Исправь ошибку в API",
  "task_id": "TASK-42",
  "repo": "backend"
}
```

Или задайте репозиторий в профиле:

```json
{
  "profiles": {
    "backend-dev": {
      "name": "Backend Developer",
      "task_worktree_repo": "backend"
    }
  }
}
```

Система создаст рабочую копию от выбранного репозитория. Все операции — коммит, слияние, очистка — выполняются в этом репозитории.

### Рабочая директория

Задайте начальную папку агента параметром `working_dir`:

```json
{
  "working_dir": "backend/services/api"
}
```

Агент увидит эту папку как корень своего проекта. Это ускоряет работу. Агент не тратит внимание на нерелевантные части проекта.

### Правила

- Папка должна существовать внутри директории проекта.
- Параметр при запуске сильнее параметра в профиле.
- При возобновлении сеанса менять эти параметры запрещено. Сеанс сохраняет свои границы.
- Система показывает, в каком репозитории работает агент. Проверьте это в сведениях о сеансе.

## 3. Ограничение записи

### Что это

Области записи (`write_scopes`) разрешают агенту менять только заданные файлы и папки. Остальное запрещено.

### Пример

Агент работает только с серверной частью:

```json
{
  "profiles": {
    "backend-mechanic": {
      "name": "Backend Mechanic",
      "permission_mode": "autonomous",
      "tool_permissions": {
        "tools": {
          "edit_file": {
            "write_scopes": ["backend/**"]
          }
        }
      }
    }
  }
}
```

Агент изменит `backend/src/main.rs`. Агент не изменит `frontend/src/app.js`.

### Правила

- Задайте шаблон пути: `backend/**` (вся папка), `.env*` (файлы по маске), `.github/**`.
- Все операции изменения подчиняются границам: правка, создание, удаление, перемещение.
- Границы действуют на всех уровнях. Агент с рабочей копией проходит две проверки: границы копии, затем области записи.
- Режим профиля `unrestricted` отключает области записи. Границы рабочей копии остаются.
- Операция вне границ отклоняется. Агент получает отказ с указанием причины.

## 4. Защита служебных файлов

### Какие файлы защищены

Файлы и папки с именем на точку — это настройки, секреты и служебные данные. Примеры: `.env`, `.git`, `.zed`, `.github`, `.agents`.

Такие файлы защищены от записи по умолчанию. Защита действует всегда и снимается только явной областью записи в профиле.

### Как действует защита

| Инструмент | Действие защиты |
|---|---|
| Правка и запись файлов | Операция требует вашего подтверждения. В автономном режиме операция запрещена. |
| Удаление и перемещение | Те же правила. |
| Терминал | Команды разбиваются на цели записи. Цели с точкой проверяются отдельно. Примеры: `echo x > .env`, `rm .git/config`, `mv file .backup`, `touch .env`, `tee .env`. |
| Обход через путь | Запись по пути с обходом (`src/../.env`) распознаётся и блокируется. |
| Симлинки | Ссылка, ведущая в защищённую зону, распознаётся. Запись блокируется. |

### Что защищено сильнее остального

| Объект | Правило |
|---|---|
| `.git` | Только чтение. Всегда. Запись запрещена всеми инструментами. Разрешение не выдаётся. |
| Верхний уровень точечных файлов | Песочница терминала блокирует запись. |
| `.zed/` (настройки проекта) | Требуют отдельного подтверждения. Область записи снимает требование. |
| `.env` и секреты | Требуют подтверждения. Явная область записи снимает требование. |

### Как разрешить запись

Задайте точную область записи в профиле:

```json
"write_scopes": [".env*", ".github/**"]
```

Правило: разрешайте минимальную зону. Не используйте `**` для всех файлов.

## 5. Чистый контекст

### Что это

Каждый субагент начинает с пустой историей. Он не видит диалог родителя.

### Зачем

- История родителя содержит много лишнего. Лишнее снижает качество ответа.
- Субагент получает только вашу задачу. Он решает её без постороннего шума.
- Системные правила субагента содержат только его рабочую копию. Основной проект не отвлекает его.
- Субагент получает только нужные для работы инструменты, скиллы.

### Что делать

- Передайте субагенту полную постановку задачи. Он не знает контекста разговора.
- Продолжайте диалог тем же сеансом по `session_id`. Не создавайте дубликат.
- Возобновлённый сеанс сохраняет свою изоляцию и базу ветки. Сменить их нельзя.

### Ограничения делегирования

Родительский агент не может плодить субагентов без контроля:

| Ограничение         | Действие                                          |
| ------------------- | ------------------------------------------------- |
| Глубина вложенности | Лимит цепочки «агент → субагент → субагент».      |
| Число одновременно  | Родитель держит лимит параллельных субагентов.    |
| Разрешённые профили | Профиль родителя задаёт, кого он может запускать. |

## 6. Безопасный терминал

### Песочница

Команды терминала выполняются в песочнице операционной системы:

- macOS: Seatbelt.
- Linux: Bubblewrap.
- Windows: Bubblewrap через WSL.

Доступ по умолчанию:

| Действие | Разрешение |
|---|---|
| Читать файлы | Да |
| Записывать в рабочую копию проекта | Да |
| Записывать в `.git` | Нет. Только чтение. Всегда. |
| Записывать в точечные файлы верхнего уровня | Нет |
| Записывать вне проекта | Нет |
| Выход в сеть | Нет |
| Локальные сокеты | Нет |

### Запрос дополнительных прав

Агенту нужна сеть или запись вне проекта? Он попросит разрешение. Вы видите причину запроса. Выберите срок: «один раз», «до конца сеанса», «всегда».

| Запрос агента | Что разрешает |
|---|---|
| `allow_hosts: ["github.com", "*.npmjs.org"]` | Сеть только для указанных сайтов |
| `allow_all_hosts` | Любую сеть |
| `fs_write_paths` | Запись в указанные папки |
| `allow_fs_write_all` | Запись везде, кроме `.git` |
| `unsandboxed` | Команду без песочницы |

Правила:

- Агент обязан указать причину запроса. Запрос без причины отклонён.
- Разрешение на сайты действует точно и на поддомены по маске.
- Система предупреждает о доменах и путях с невидимыми Unicode-символами (настройка `warn_confusable_unicode`).
- На Windows ограничение по сайтам недоступно. Используйте `allow_all_hosts`.
- `unsandboxed` на Windows меняет оболочку: WSL bash на shell хоста. Учитывайте формат путей.

### Жёсткие запреты

Эти запреты нельзя отключить настройками:

- Удаление корня файловой системы, домашней папки, текущей и родительской папки. Примеры: `rm -rf /`, `rm -rf ~`, `rm -rf .`, `rm -rf ..`.
- Обход запрета через обходные пути (`/tmp/../../`) или цепочки команд.
- Подстановки shell в командах: `$VAR`, `$(...)`, обратные кавычки, `<(...)`, `>(...)`. Агент получит отказ с пояснением.

## 7. Изоляция инструментов

### Набор инструментов

Профиль включает и отключает инструменты агента. Пример: агенту-исследователю доступны чтение и поиск. Редактирование отключено:

```json
{
  "profiles": {
    "researcher": {
      "name": "Researcher",
      "tools": {
        "read_file": true,
        "grep": true,
        "edit_file": false
      }
    }
  }
}
```

Запуск агента с пустым набором инструментов запрещён. Система сообщит об ошибке.

### Режимы подтверждения

Профиль задаёт режим работы инструментов:

| Режим | Поведение |
|---|---|
| `interactive` | Опасное действие требует вашего подтверждения. |
| `autonomous` | Агент действует сам. Действие с подтверждением запрещено. Без списка правил все операции запрещены. |
| `unrestricted` | Всё разрешено. Кроме жёстких запретов терминала. |

Порядок приоритета правил: жёсткие запреты → глобальный запрет → запрет профиля → подтверждение → разрешение.

## Типичные сценарии

**Два агента правят одни файлы.**
Запустите каждого в своей задаче. Каждый получит свою рабочую копию. Конфликт изменений исключён до слияния.

**Агент не должен трогать фронтенд.**
Задайте профиль с `write_scopes: ["backend/**"]`.

**Проект — монорепозиторий. Агент работает с одной частью.**
Задайте `repo` и `working_dir` при запуске. Агент получит только нужную часть.

**Агенту нужно изменить `.env`.**
Задайте область записи `".env*"` в профиле. Без области операция потребует подтверждения или будет запрещена.

**Агенту нужен интернет для установки пакетов.**
Не разрешайте заранее. Агент запросит доступ к нужным сайтам. Одобрьте запрос на один раз.

**Боитесь опасных команд.**
Песочница работает по умолчанию. Запись в `.git` и удаление критических папок заблокированы всегда.
