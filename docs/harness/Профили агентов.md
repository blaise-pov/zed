# Профили агентов

Профиль агента определяет поведение и права доступа ИИ агента.
Профили задают специализированные роли для решения разных инженерных задач.
Каждый профиль настраивает:
- модель
- описание роли агента (промпт)
- доступные системные инструменты и инструменты MCP-серверов
- доступные скилы
- правила делегирования (перечень профилей агентов, которые он может использовать для запуска сабагентов)
- режим изоляции

---
## 1. Настройка профилей

Профили объявляются в секции `agent.profiles` пользовательского или проектного файла настроек.

```json
{
  "agent": {
    "default_profile": "code_mechanic",
    "profiles": {
      "code_mechanic": {
        "name": "Code Mechanic",
        "description": "Точечное исправление багов и рефакторинг",
        "default_model": {
          "provider": "anthropic",
          "model": "claude-3-5-haiku-latest"
        },
        "custom_prompt_path": ".zed/prompts/code_mechanic.md",
        "tools": {
          "read_file": true,
          "edit_file": true,
          "terminal": true,
          "spawn_agent": false
        },
        "task_isolation": "required",
        "skills": ["rust-conventions"]
      }
    }
  }
}
```

---

## 2. Основные параметры конфигурации

| Параметр             | Тип     | Описание                                                                     |
| :------------------- | :------ | :--------------------------------------------------------------------------- |
| `name`               | Строка  | Отображаемое имя профиля в интерфейсе                                        |
| `description`        | Строка  | Описание роли. Отображается другим агентам при делегировании                 |
| `default_model`      | Объект  | Модель ИИ: провайдер, идентификатор модели и блок рассуждений                |
| `custom_prompt_path` | Строка  | Путь к Markdown-файлу с инструкциями роли                                    |
| `tools`              | Словарь | Включение (`true`) или отключение (`false`) встроенных инструментов          |
| `context_servers`    | Словарь | Активные MCP-серверы и их разрешенные инструменты                             |
| `skills`             | Массив \| `null` | Белый список навыков из папки `.agents/skills`. При `null` встроенные профили видят все навыки, кастомные — ни одного. Пустой массив `[]` блокирует все |
| `delegation`         | Объект  | Разрешенные субагенты (`allowed`) и предельная глубина вызовов (`max_depth`) |
| `task_isolation`     | Строка  | Режим изоляции на базе worktree: `required`, `optional`, `disabled`.         |
| `tool_permissions`   | Объект  | Правила подтверждений и зоны разрешенной записи `write_scopes`               |

## 3. Доступность инструментов и права выполнения

Различайте доступность инструмента в профиле и права доступа:

- **Профиль агента (`agent.profiles.tools`)** определяет видимость инструмента. Отключенный инструмент агент вызвать не может.
- **Права доступа (`agent.profiles.tool_permissions`)** определяют политику выполнения разрешенного инструмента.
  Можно определить поведение по умолчанию для всех инструментов профиля:
  - `allow` — инструмент выполняется автоматически.
  - `confirm` — редактор запрашивает подтверждение пользователя.
  - `deny` — действие блокируется системой безопасности.

Определить или переопределить политику для каждого инструмента:
```Json
"tool_permissions": {
  "default": "deny",
  "tools": {
	"edit_file": {
	  "default": "allow",
	  "write_scopes": [
		"docs/**",
		"README.md"
	  ]
	},
	"terminal": {
	  "default": "deny",
	  "always_allow": [
		{
		  "pattern": "^git\\s+(status|diff|log)\\b"
		}
	  ]
	},
	"grep": { "default": "allow" }
  }
}
```


Глобально запретить опасный инструмент для всех профилей.
```Json
{
  "agent": {
    "tool_permissions": {
      "tools": {
        "terminal": {
          "default": "deny"
        }
      }
    },
    "profiles": {
      "custom_worker": {
        "tools": {
          "terminal": true
        },
        "tool_permissions": {
          "tools": {
            "terminal": {
              "default": "allow"
            }
          }
        }
      }
    }
  }
}

```
Глобальный deny проверяется первым.
Если глобальное правило вернуло Deny, правило профиля allow игнорируется.

## 4. Делегирование

Блок `delegation` разрешает агенту запускать сабагентов. Без блока профиль — solo-агент: инструмент `spawn_agent` недоступен.

```json
"delegation": {
  "allowed": ["code_mechanic", "github_researcher"],
  "max_depth": 2
}
```

- `allowed` — перечень идентификаторов профилей, которых агент имеет право порождать.
- `max_depth` — предельная глубина цепочки делегирования (диапазон `1..=5`).

Глобальные лимиты вложенности задаются в секции `agent.nested_sub_agents` (`enabled`, `max_depth`, `max_concurrent`). Подробнее — в документе [Параметры settings.json](./Параметры%20settings.json.md).
