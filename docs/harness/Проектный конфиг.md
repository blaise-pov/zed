## 1. Назначение

Проектный конфиг задаёт параметры работы агентов в рамках одного проекта.
Конфиг действует только в своём проекте. Он не изменяет глобальные настройки редактора.

Подробное описание полей профилей — в документе «Профили агентов». Этот документ описывает конфиг: файл, приоритеты, состав, подключения.

## 2. Расположение и формат

Файл конфига: `.zed/settings.json` в корне проекта.

Откройте файл командой **Open Project Settings** в палитре команд.

Формат — JSON. Файл поддерживает комментарии `//`.

Добавьте файл в git. Тогда вся команда получит одинаковые настройки агентов.

Допустимы дополнительные файлы настроек в подпапках проекта. Они переопределяют файл корня для своей папки.

## 3. Приоритет слоёв

Настройки применяются слоями:

1. Встроенные значения по умолчанию.
2. Пользовательские настройки.
3. Файлы настроек проекта.

Каждый следующий слой переопределяет предыдущий. Объекты сливаются по ключам. Скалярные значения заменяются целиком.

Пример. Пользователь задал профиль `lead`. Проект задал профиль `backend`. В проекте доступны оба профиля. Одноимённые ключи берут значение из проекта.

## 4. Состав конфига

```json
// .zed/settings.json
{
  "agent": {
    "default_profile": "write",
    "profiles": {},
    "context_servers": {}
  },
  "context_servers": {},
  "context_server_timeout": 60
}
```

| Ключ | Назначение |
|---|---|
| `agent.profiles` | Профили проекта. Формат полей — в документе «Профили агентов» |
| `agent.default_profile` | Профиль по умолчанию для новых сессий этого проекта |
| `agent.context_servers` | Объявления MCP-серверов внутри блока `agent`. Приоритет выше, чем у `context_servers` |
| `context_servers` | Объявления MCP-серверов верхнего уровня |
| `context_server_timeout` | Таймаут вызовов инструментов для всех серверов, секунды. По умолчанию 60 |

Размещайте все параметры агентов в одном блоке `agent`. Так конфиг остаётся читаемым.

## 5. Профили в проекте

Проект хранит профили в `agent.profiles`.

Профили проекта дополняют пользовательские профили. При открытии проекта доступны оба набора. Профиль с одинаковым идентификатором берётся из проекта.

Профиль, созданный в панели агента, сохраняется в один из двух файлов:

- в пользовательские настройки — глобально;
- в `.zed/settings.json` — только для проекта.

Выберите место сохранения при создании профиля.

Идентификатор профиля — ключ в `agent.profiles`. Пишите идентификаторы латиницей в kebab-case: `backend`, `code-reviewer`.

Пример записи профиля в проекте:

```json
{
  "agent": {
    "default_profile": "backend",
    "profiles": {
      "backend": {
        "name": "Backend"
      }
    }
  }
}
```

Описание всех полей профиля — в документе «Профили агентов».

## 6. Подключения MCP-серверов

### 6.1. Принцип

MCP — протокол подключения внешних инструментов. Сервер MCP даёт агенту дополнительные инструменты.

Настройка подключения проходит в два шага:

1. Объявите сервер в конфиге проекта.
2. Разрешите сервер в профиле. Порядок разрешения — в документе «Профили агентов».

Объявите сервер один раз. Все профили проекта используют одно объявление.

### 6.2. Где объявлять сервер

Допустимы два места:

- ключ `context_servers` верхнего уровня;
- ключ `agent.context_servers` внутри блока `agent`.

Записи из `agent.context_servers` имеют приоритет. Не дублируйте один сервер в двух местах.

Имя сервера — ключ в `context_servers`. Используйте его в профиле для разрешения доступа.

### 6.3. Тип подключения: локальный процесс

Тип `stdio` запускает команду на машине пользователя.

```json
"context_servers": {
  "github": {
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-github"],
    "env": {
      "GITHUB_TOKEN": "$GITHUB_TOKEN"
    },
    "timeout": 120
  }
}
```

Значения переменных окружения подставляются: запись `"$GITHUB_TOKEN"` раскрывается в значение переменной окружения машины. Не храните секреты в файле (раздел 9).

Поля:

| Поле | Тип | Назначение |
|---|---|---|
| `command` | строка | Исполняемая команда |
| `args` | массив | Аргументы команды |
| `env` | объект | Переменные окружения процесса |
| `timeout` | число | Таймаут вызова инструмента, секунды. По умолчанию 60 |
| `platforms` | объект | Команда отдельно для каждой ОС |
| `enabled` | bool | Запуск сервера. По умолчанию `true` |
| `remote` | bool | Запуск на удалённом сервере при удалённой разработке. По умолчанию `false` |

Разные команды по платформам:

```json
"context_servers": {
  "my-server": {
    "command": "./bin/mcp-linux",
    "platforms": {
      "windows": { "command": ".\\bin\\mcp-win.exe" },
      "darwin-arm64": { "command": "./bin/mcp-mac" }
    }
  }
}
```

### 6.4. Тип подключения: удалённый сервер

Тип `http` подключается по адресу.

```json
"context_servers": {
  "docs-search": {
    "url": "https://mcp.example.com/docs",
    "headers": {
      "Authorization": "Bearer ваш-токен"
    },
    "timeout": 120
  }
}
```

Поля:

| Поле | Тип | Назначение |
|---|---|---|
| `url` | строка | Адрес сервера |
| `headers` | объект | Заголовки запросов |
| `timeout` | число | Таймаут вызова, секунды. По умолчанию — значение `context_server_timeout` |
| `oauth` | объект | Данные регистрации OAuth-клиента |
| `enabled` | bool | Подключение сервера. По умолчанию `true` |

### 6.5. Тип подключения: расширение

Тип `extension` настраивается расширением IDE.

```json
"context_servers": {
  "my-extension-server": {
    "enabled": true,
    "settings": {
      "option": "value"
    }
  }
}
```

Поля:

| Поле | Тип | Назначение |
|---|---|---|
| `settings` | объект | Параметры сервера. Формат задаёт документация расширения |
| `enabled` | bool | Запуск сервера. По умолчанию `true` |
| `remote` | bool | Запуск на удалённом сервере. По умолчанию `false` |

### 6.6. Таймауты

Сервер без `timeout` использует `context_server_timeout`.

Задайте общий таймаут один раз в корне конфига:

```json
{
  "context_server_timeout": 90
}
```

Таймаут отдельного сервера переопределяет общий.

## 7. Полный пример конфига

```json
// .zed/settings.json
{
  "agent": {
    "default_profile": "backend",
    "profiles": {
      "backend": { "name": "Backend" },
      "reviewer": { "name": "Reviewer" }
    },
    "context_servers": {
      "github": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "env": { "GITHUB_TOKEN": "$GITHUB_TOKEN" },
        "timeout": 120
      }
    }
  },
  "context_servers": {
    "docs-search": {
      "url": "https://mcp.example.com/docs",
      "headers": { "Authorization": "Bearer ваш-токен" }
    }
  },
  "context_server_timeout": 60
}
```

## 8. Проверка конфига

1. Сохраните файл.
2. Откройте настройки MCP. Проверьте статус серверов.
3. Откройте селектор профилей. Проверьте, что профили проекта видны.
4. Пошлите агенту тестовый запрос.

## 9. Правила работы с конфигом

- Храните файл в git. Так команда получает одну конфигурацию.
- Не вставляйте секреты в файл. Используйте переменные окружения машины.
- Не дублируйте сервер в `context_servers` и в `agent.context_servers`.
- Удаляйте из конфига неиспользуемые серверы. Каждый сервер занимает ресурсы при запуске.
